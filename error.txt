첨부한 이미지는 Apple이 실제 iOS 26에서 구현한 UISegmentedControl의 시각적 기준이다.

이 이미지를 단순한 분위기 참고용으로 보지 마라. 최종 결과의 외형을 검증하는 기준 이미지로 사용하라.

각 자료의 우선순위와 역할은 다음과 같다.

1. 기존 CupertinoSegmentedControl 코드
    * public API
    * 상태 관리
    * 선택 동작
    * 레이아웃 계약
    * 접근성
    * 기존 호환성
2. 첨부한 실제 iOS 26 이미지
    * 전체 비율
    * 컨테이너 높이
    * 외부 capsule 형태
    * 내부 여백
    * segment 간격
    * 선택 indicator 크기와 위치
    * glass 명암
    * border와 highlight의 강도
    * 텍스트 정렬
    * 선택 및 비선택 상태의 시각적 대비
    * 최종 외형의 판정 기준
3. 프로젝트의 CupertinoNavigationBar 구현
    * backdrop 구성
    * drawBackdrop 사용 방식
    * LayerBackdrop 구성
    * rememberCombinedBackdrop
    * vibrancy
    * blur
    * lens
    * highlight
    * shadow
    * inner shadow
    * DampedDragAnimation
    * InteractiveHighlight
    * press 및 drag deformation
    * iOS 26 glass 효과를 Compose로 구현하는 기술적 기준

중요:

* 이미지의 외형을 NavigationBar의 레이아웃 그대로 복사하지 마라.
* NavigationBar의 크기, 높이, item width, icon/label 구조는 segmented control에 적용하지 마라.
* NavigationBar에서 재사용해야 하는 것은 iOS 26 glass 효과의 구현 원리와 interaction 패턴이다.
* SegmentedControl의 형상과 치수는 첨부 이미지 및 기존 SegmentedControl 구조를 기준으로 결정하라.
* 이미지에 보이지 않는 효과를 자의적으로 추가하지 마라.
* NavigationBar에 있다는 이유만으로 모든 효과를 무조건 동일 강도로 적용하지 마라.
* 이미지에 나타난 강도와 구조에 맞게 같은 구현 원리를 최소 조정하라.

코드를 수정하기 전에 첨부 이미지를 관찰하여 다음 항목을 먼저 문서화하라.

이미지 관찰 결과

* 전체 컨테이너의 가로·세로 비율
* 외부 모서리 형태

대신 다음 순서로 값을 결정하라.

1. 기존 CupertinoSegmentedControl의 치수
2. 이미지에서 관찰되는 상대 비율
3. NavigationBar에서 사용한 glass 효과 값
4. 최소한의 조정

이미지와 코드의 역할 충돌 처리

첨부 이미지와 NavigationBar 구현이 다르게 보이는 경우:

* 최종 외형은 첨부 이미지를 우선한다.
* glass 효과를 구현하는 방법은 NavigationBar를 우선한다.
* 기존 API와 동작은 기존 SegmentedControl을 우선한다.

예:

* NavigationBar 높이가 64.dp여도 SegmentedControl 높이를 64.dp로 만들지 마라.
* NavigationBar indicator 높이가 56.dp여도 그대로 복사하지 마라.
* NavigationBar의 blur/lens 구조는 재사용하되 segmented control 이미지에 맞게 강도와 크기를 최소 조정하라.
* NavigationBar에 icon과 label이 있어도 SegmentedControl content 구조를 변경하지 마라.

이미지만 보고 새로운 구현을 만들지 말고, 기존 SegmentedControl을 유지하면서 NavigationBar의 기술적 패턴으로 이미지의 외형을 재현하라.

+

현재 compose-hig 라이브러리의 CupertinoSegmentedControl을 iOS 18 스타일에서 iOS 26 스타일로 업데이트한다.

이 작업의 유일한 구현 기준은 이미 프로젝트에 구현된 CupertinoNavigationBar다.

이 작업은 새로운 스타일을 설계하는 작업이 아니다.

CupertinoNavigationBar의 glass 구조, backdrop 구성, interaction 처리, drag animation, selection indicator, modifier 순서를 분석한 뒤 그 구현 패턴을 CupertinoSegmentedControl의 구조에 맞게 최소한으로 이식해야 한다.

NavigationBar를 단순히 시각적 참고로만 사용하지 마라.

자의적으로 iOS 26 스타일을 해석하거나, 새로운 효과를 추가하거나, 기존 구현과 다른 방식으로 재작성하지 마라.

⸻

기준 구현

다음 CupertinoNavigationBar 구현을 기준으로 사용하라.

특히 아래 구조와 값은 반드시 실제 코드에서 확인하고 대응시켜라.

전체 구조

CupertinoNavigationBar는 하나의 UI를 다음 3개 레이어로 구성한다.

1. Background Row
2. Accent color overlay Row
3. Sliding selection indicator Box

CupertinoSegmentedControl도 같은 3단계 레이어 구조를 기본으로 사용하라.

단, segmented control의 기존 API와 레이아웃 계약은 유지해야 한다.

⸻

1. Background layer

기준 구현은 다음 특성을 가진다.

.drawBackdrop(
    backdrop = backdrop,
    shape = { ContinuousCapsule() },
    effects = {
        vibrancy()
        blur(2.dp.toPx())
        lens(24.dp.toPx(), 24.dp.toPx())
    },
    layerBlock = {
        val progress = dampedDragAnimation.pressProgress
        val scale = lerp(1f, 1f + 16.dp.toPx() / size.width, progress)
        scaleX = scale
        scaleY = scale
    },
    onDrawSurface = {
        drawRect(containerColor)
    }
)
.then(interactiveHighlight.modifier)

CupertinoSegmentedControl의 전체 컨테이너도 이 구조를 기준으로 구현하라.

반드시 확인할 것:

* ContinuousCapsule
* vibrancy()
* blur(2.dp.toPx())
* lens(24.dp.toPx(), 24.dp.toPx())
* press progress에 따른 전체 컨테이너 scale
* InteractiveHighlight.modifier
* containerColor.copy(alpha = 0.6f) 계열 처리
* modifier 순서

새로운 blur 값, lens 값, shadow 또는 gradient를 임의로 만들지 마라.

segmented control 크기 때문에 값 조정이 필요한 경우에도 먼저 동일 값을 사용하고, 실제 레이아웃 문제가 있는 경우에만 최소한으로 조정하라.

조정한 값은 최종 보고에서 반드시 이유를 설명하라.

⸻

2. Accent overlay layer

기준 구현은 두 번째 Row를 다음 방식으로 겹친다.

.clearAndSetSemantics {}
.alpha(0f)
.layerBackdrop(tabsBackdrop)
.graphicsLayer {
    translationX = panelOffset
}
.drawBackdrop(
    backdrop = backdrop,
    shape = { ContinuousCapsule() },
    effects = {
        val progress = dampedDragAnimation.pressProgress
        vibrancy()
        blur(8.dp.toPx())
        lens(
            24.dp.toPx() * progress,
            24.dp.toPx() * progress
        )
    },
    highlight = {
        val progress = dampedDragAnimation.pressProgress
        Highlight.Default.copy(alpha = progress)
    },
    onDrawSurface = {}
)
.then(interactiveHighlight.modifier)
.graphicsLayer(
    colorFilter = ColorFilter.tint(accentColor)
)

CupertinoSegmentedControl에서도 선택된 segment의 content tint 또는 accent 표현을 위해 동일한 overlay 방식을 우선 사용하라.

중요:

* 선택된 segment의 텍스트를 단순히 color = accentColor로 바꾸는 방식으로 대체하지 마라.
* NavigationBar와 동일하게 content layer를 별도로 구성하고 ColorFilter.tint(accentColor)로 tint하는 방식을 우선 적용하라.
* overlay는 semantics에서 제거하라.
* 원본 content와 overlay content가 중복으로 접근성 노드에 나타나지 않게 하라.
* rememberLayerBackdrop()을 사용한 중간 backdrop 레이어 구조를 유지하라.
* alpha(0f)와 layerBackdrop()의 의미와 modifier 순서를 임의로 바꾸지 마라.

기존 segmented control 구조상 overlay content 복제가 불가능하다면 임의 구현으로 우회하지 말고, 기존 slot 호출 구조를 분석하여 안전하게 같은 content를 두 레이어에 렌더링할 방법을 찾아라.

⸻

3. Sliding selection indicator

NavigationBar의 selection indicator는 단순 배경 박스가 아니다.

다음 구성을 동일한 구현 기준으로 삼아라.

.drawBackdrop(
    backdrop = rememberCombinedBackdrop(backdrop, tabsBackdrop),
    shape = { ContinuousCapsule() },
    effects = {
        val progress = dampedDragAnimation.pressProgress
        lens(
            10.dp.toPx() * progress,
            14.dp.toPx() * progress,
            chromaticAberration = true
        )
    },
    highlight = {
        val progress = dampedDragAnimation.pressProgress
        Highlight.Default.copy(alpha = progress)
    },
    shadow = {
        val progress = dampedDragAnimation.pressProgress
        Shadow(alpha = progress)
    },
    innerShadow = {
        val progress = dampedDragAnimation.pressProgress
        InnerShadow(
            radius = 8.dp * progress,
            alpha = progress
        )
    },
    layerBlock = {
        scaleX = dampedDragAnimation.scaleX
        scaleY = dampedDragAnimation.scaleY
        val velocity = dampedDragAnimation.velocity / 10f
        scaleX /= 1f - (velocity * 0.75f)
            .fastCoerceIn(-0.2f, 0.2f)
        scaleY *= 1f - (velocity * 0.25f)
            .fastCoerceIn(-0.2f, 0.2f)
    },
    onDrawSurface = {
        val progress = dampedDragAnimation.pressProgress
        drawRect(
            if (isLightTheme) {
                Color.Black.copy(alpha = 0.1f)
            } else {
                Color.White.copy(alpha = 0.1f)
            },
            alpha = 1f - progress
        )
        drawRect(
            Color.Black.copy(alpha = 0.03f * progress)
        )
    }
)

CupertinoSegmentedControl의 selected indicator는 반드시 이 패턴을 기준으로 구현하라.

다음 요소를 빠뜨리지 마라.

* rememberCombinedBackdrop(backdrop, tabsBackdrop)
* press progress 기반 lens
* chromaticAberration = true
* press progress 기반 highlight
* press progress 기반 shadow
* press progress 기반 inner shadow
* drag velocity 기반 x/y deformation
* light/dark theme별 surface tint
* selected indicator의 capsule shape
* indicator 자체에 gesture modifier 연결

단순히:

background(...)
animateDpAsState(...)

형태로 구현하지 마라.

4. Drag 및 press interaction

NavigationBar는 DampedDragAnimation을 사용한다.

다음 패턴을 반드시 조사하고 재사용하라.

DampedDragAnimation(
    animationScope = animationScope,
    initialValue = selectedIndex.toFloat(),
    valueRange = 0f..lastIndex.toFloat(),
    visibilityThreshold = 0.001f,
    initialScale = 1f,
    pressedScale = 78f / 56f,
    onDragStarted = {},
    onDragStopped = {
        val targetIndex = targetValue
            .fastRoundToInt()
            .fastCoerceIn(0, lastIndex)
        currentIndex = targetIndex
        animateToValue(targetIndex.toFloat())
    },
    onDrag = { _, dragAmount ->
        updateValue(
            (
                targetValue +
                    dragAmount.x / itemStep *
                    if (isLtr) 1f else -1f
            ).fastCoerceIn(0f, lastIndex.toFloat())
        )
    }
)

CupertinoSegmentedControl도 가능한 한 동일한 DampedDragAnimation을 사용하라.

기존 segmented control이 탭 클릭만 지원하고 drag가 없더라도 iOS 26 스타일 구현에서 indicator drag가 요구된다면 NavigationBar와 같은 interaction 모델을 이식하라.

단, public API는 변경하지 마라.

선택 결과는 기존 onValueChange, onSelectedIndexChange 또는 이에 해당하는 기존 callback을 그대로 호출해야 한다.

다음은 유지해야 한다.

* 클릭으로 선택 가능
* drag로 선택 가능
* drag 종료 시 가장 가까운 segment로 정렬
* RTL에서 drag 방향 반전
* 외부 selected state 변경 시 indicator 동기화
* drag 중 불필요한 callback 반복 호출 방지
* 최종 index 확정 시에만 기존 callback 호출

⸻

5. InteractiveHighlight

NavigationBar는 InteractiveHighlight의 위치를 indicator 중심에 연결한다.

InteractiveHighlight(
    animationScope = animationScope,
    position = { size, _ ->
        val cx = itemCenterX(dampedDragAnimation.value)
        Offset(
            if (isLtr) {
                cx + panelOffset
            } else {
                size.width - cx + panelOffset
            },
            size.height / 2f
        )
    }
)

CupertinoSegmentedControl에서도 highlight 중심은 현재 선택 indicator의 시각적 중심을 따라야 한다.

고정 위치 highlight를 만들지 마라.

indicator가 이동하거나 drag될 때 highlight도 함께 이동해야 한다.

다음 modifier 연결 관계를 유지하라.

* container layer:
    interactiveHighlight.modifier
* accent overlay layer:
    interactiveHighlight.modifier
* selection indicator:
    interactiveHighlight.gestureModifier

⸻

6. 위치와 폭 계산

NavigationBar 구현에는 다음 함수 관계가 있다.

fun itemLeftX(index: Float): Float
fun itemCenterX(index: Float): Float

그리고 indicator 위치는 DampedDragAnimation.value에 의해 연속적으로 계산된다.

CupertinoSegmentedControl도 integer index만으로 indicator 위치를 순간 전환하지 말고, Float index를 기반으로 연속 이동하도록 구현하라.

segment 폭이 동일하다면 NavigationBar와 같은 step 계산을 사용할 수 있다.

val itemStep = itemWidthPx + itemGapPx

segment 폭이 가변이라면 임의로 균등 분할로 변경하지 마라.

기존 segmented control이 가변 폭을 지원한다면 각 segment의 실제 위치와 폭을 측정하여 다음을 계산하라.

* 현재 indicator left
* 현재 indicator width
* 다음 indicator left
* 다음 indicator width
* drag fraction에 따른 left interpolation
* drag fraction에 따른 width interpolation
* indicator center
* highlight center

기존 레이아웃 특성을 보존하면서 NavigationBar의 연속 drag 원리를 적용하라.

⸻

7. panelOffset

NavigationBar는 drag offset에 따라 전체 glass panel을 약간 이동시킨다.

val fraction = (
    offsetAnimation.value / rowWidth
).fastCoerceIn(-1f, 1f)
4.dp.toPx() *
    fraction.sign *
    EaseOut.transform(abs(fraction))

CupertinoSegmentedControl에서도 전체 container와 accent overlay가 같은 panelOffset을 공유하도록 구현하라.

indicator만 움직이고 background layer가 완전히 정지하는 별도 스타일을 새로 만들지 마라.

단, segmented control 크기에서 4.dp 이동이 과도한 경우에만 비율을 유지한 최소 조정을 허용한다.

⸻

8. shape

기준 구현은 모든 핵심 glass layer에서 ContinuousCapsule()을 사용한다.

CupertinoSegmentedControl에서도 다음에 동일한 shape 계열을 사용하라.

* 전체 container
* accent overlay
* selected indicator
* segment click clip

일반 RoundedCornerShape로 임의 변경하지 마라.

기존 public API에서 custom shape 파라미터를 제공하고 있다면 해당 API는 유지하되, 기본값은 NavigationBar 스타일과 일치하게 하라.

⸻

9. 색상

NavigationBar는 다음 색상 구조를 사용한다.

val accentColor = colors.accentColor
val containerColor = colors.containerColor.copy(alpha = 0.6f)

indicator surface는 다음 규칙을 사용한다.

if (isLightTheme) {
    Color.Black.copy(alpha = 0.1f)
} else {
    Color.White.copy(alpha = 0.1f)
}

press 상태에서는:

Color.Black.copy(alpha = 0.03f * progress)

CupertinoSegmentedControl도 동일한 색상 관계를 적용하라.

기존 CupertinoSegmentedControlColors API가 있다면 삭제하거나 NavigationBar Colors로 교체하지 마라.

기존 Colors API를 유지하면서 내부적으로 다음 대응 관계를 만들라.

* 기존 selected/accent 색상 → accent overlay tint
* 기존 container 색상 → background surface
* disabled 색상 → 기존 API 유지
* light/dark indicator tint → NavigationBar와 동일 규칙

새로운 public 색상 파라미터를 추가하지 마라.

외부 API는 유지하고 내부 렌더링 구현만 iOS 26 스타일로 교체하라.

11. 중복 호출과 안전성

NavigationBar는 동일한 content를 background Row와 accent overlay Row에서 두 번 호출한다.

CupertinoSegmentedControl에서도 동일한 방식이 필요할 수 있다.

하지만 다음 문제를 반드시 확인하라.

* content lambda 내부에 부수 효과가 없는가
* 동일 item callback이 중복으로 등록되지 않는가
* overlay layer가 클릭을 가로채지 않는가
* overlay layer가 semantics에 노출되지 않는가
* 중복 layer가 layout size를 변경하지 않는가
* 숨겨진 layer가 pointer input을 받지 않는가

필요하다면 overlay layer에 다음을 적용하라.

.clearAndSetSemantics {}

overlay layer에는 실제 클릭 처리를 연결하지 마라.

클릭과 drag gesture는 실제 foreground 또는 indicator layer에서만 처리하라.

⸻

12. RenderNode 안전성

이 프로젝트에서는 Android RenderThread의 RenderNode::prepareTreeImpl 재귀 스택 오버플로 문제가 발생한 적이 있다.

따라서 다음을 절대 만들지 마라.

* backdrop이 자기 자신의 layerBackdrop을 다시 참조하는 순환 구조
* rememberCombinedBackdrop()에 동일한 backdrop을 중복 연결
* 동일 Modifier 인스턴스를 재귀적으로 .then()하는 구조
* content가 자기 자신을 다시 호출하는 구조
* 무한 중첩된 graphicsLayer
* drawBackdrop 내부에서 동일 layer를 다시 생성하는 구조
* Composable 재귀 호출
* measure 또는 subcompose 재귀

NavigationBar의 구조를 따라가되, 다음 관계를 정확히 유지하라.

external backdrop
    ├─ background container
    ├─ accent overlay → tabsBackdrop에 기록
    └─ indicator → combined(external backdrop, tabsBackdrop)

다음과 같은 순환은 만들지 마라.

tabsBackdrop
    → combinedBackdrop
    → tabsBackdrop

또는:

indicator backdrop
    → indicator 자신이 기록하는 layerBackdrop

검증 조건

수정 후 반드시 검증하라.

1. 기존 public API가 유지되는가
2. 프로젝트가 컴파일되는가
3. 선택 클릭이 정상인가
4. 선택 indicator가 올바른 위치로 이동하는가
5. indicator drag가 정상인가
6. drag 종료 시 가장 가까운 segment로 정렬되는가
7. 외부 selected state 변경이 반영되는가
8. RTL에서 위치와 drag 방향이 정상인가
9. light theme이 정상인가
10. dark theme이 정상인가
11. disabled 상태가 정상인가
12. overlay가 semantics에 중복 노출되지 않는가
13. overlay가 클릭을 가로채지 않는가
14. backdrop 순환이 없는가
15. 불필요한 graphicsLayer 중첩이 없는가
16. NavigationBar와 나란히 배치했을 때 동일한 iOS 26 glass 계열로 보이는가
17. Android에서 RenderThread 크래시가 발생하지 않는가

가능한 빌드 및 테스트를 직접 실행하라.

테스트를 실행할 수 없는 경우 그 이유를 명확히 적어라.
